# Request: Agent 3 → Agent 1 — database conventions

Agent 3's worker (`apps/worker`) and media module (`@honeytree/media`) talk to PostgreSQL with
plain SQL through `pg`, not through the Prisma client. That keeps them independent of your
generated client, but it means the physical schema must match PLAN.md §3.1 exactly.
**Please follow these conventions in `schema.prisma`.** Agent 3 verifies them with
`pnpm --filter @honeytree/worker check:schema` (introspects the live database and lists every
table and column Agent 3 reads or writes), which will run in CI once your migration lands.

1. **Table and column names are the snake_case names in PLAN.md §3.1.** Use `@@map("games")` and
   `@map("owner_id")` etc. Table names are plural snake_case: `users`, `sessions`, `games`,
   `media`, `game_likes`, `reviews`, `comments`, `comment_likes`, `karma_events`, `downloads`,
   `game_scores`, `reports`.
2. **IDs are UUIDs generated by the database:**
   `id String @id @default(dbgenerated("gen_random_uuid()")) @db.Uuid`. Foreign keys are
   `@db.Uuid`. (Prisma's `@default(uuid())` is applied by the client, so raw SQL inserts would
   fail.) Join tables keep the composite primary keys from §3.1.
3. **Timestamps are `timestamptz` with a database default:** `@default(now()) @db.Timestamptz`.
   `updated_at` columns may use `@updatedAt`; Agent 3 always sets them explicitly in SQL.
4. **Enums:** either native Postgres enums or `text` columns are fine. Values are exactly the
   lowercase strings in §3.1 (`media.kind`: `build|screenshot|video|cover|avatar`,
   `media.status`: `uploading|scanning|processing|ready|rejected`, `games.status`:
   `draft|published|unpublished|removed`). Agent 3 compares with plain string literals.
5. **Arrays and json:** `games.tags` and `games.platforms` are `text[]`; `users.links` and
   `media.variants` are `jsonb` (`media.variants` defaults to `{}`; Agent 3 never writes NULL).
6. **`media.size_bytes` is `BigInt`** (a 2 GB build does not fit in a 32-bit integer). Prisma returns
   it as a JS `bigint`; `serializeMedia` accepts that. `media.sort_order` is `Int` default 0.
7. **Counter columns** (`likes_count`, `downloads_count`, `comments_count`, `reviews_count`,
   `rating_avg`, `rating_count`, `likes_received_total`, `games_count`, `karma_total`) are
   `NOT NULL DEFAULT 0` (`rating_avg` is `double precision`/`numeric`, default 0).
8. **`game_scores`** is created by your migration. Agent 3's worker upserts it with
   `INSERT ... ON CONFLICT (game_id)`, so `game_id` must be the primary key (§3.1 already says so).
9. **Extensions:** enable `pg_trgm` in your first migration (`CREATE EXTENSION IF NOT EXISTS`).
   The local postgres container already creates it, but production should not rely on that.

## What Agent 3 reads and writes

| Table                                               | Agent 3 reads                                                                        | Agent 3 writes                                                                                                                                                |
| --------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `games`                                             | `id, owner_id, status, published_at, created_at, cover_media_id, rating_*`, counters | `cover_media_id` (when a cover reaches `ready` or is deleted), `downloads_count`, nightly drift fixes of every counter                                        |
| `users`                                             | `id, role`                                                                           | `avatar_media_id` (when an avatar reaches `ready`), nightly drift fixes of `karma_total`, `likes_received_total`, `games_count`, `rating_avg`, `rating_count` |
| `media`                                             | all                                                                                  | all (the media module owns this table's lifecycle)                                                                                                            |
| `downloads`                                         | all                                                                                  | insert                                                                                                                                                        |
| `game_scores`                                       | –                                                                                    | upsert every 5 minutes                                                                                                                                        |
| `game_likes`, `reviews`, `comments`, `karma_events` | counts and timestamps                                                                | –                                                                                                                                                             |
